# Release 1.0.0 — MVP

**Release date:** 2026-11-11
**Status:** Released (MVP), deployment verified on 2026-11-11.
**Application version:** `1.0.0` ([`VERSION`](../reviews/phase10_closeout.md),
`APP_VERSION`, `/health/live`).
**Review:** [`../reviews/phase10_closeout.md`](../reviews/phase10_closeout.md)

This is the first complete MVP release: a deployable, single-host Docker
Compose application with real TripoSR object generation, real COLMAP/OpenMVS
scene reconstruction, asynchronous task tracking, in-browser viewing, GLB
download, failure handling and durable projects/assets.

---

## 1. What is included

| Capability | Implementation |
|---|---|
| Registration / authentication | Email + Argon2id password, server session, signed double-submit CSRF, Secure HttpOnly cookie in production, auth rate limiting, hourly expired/revoked session cleanup |
| Project management | Create/list/detail/delete, ownership enforcement, pagination and filters |
| Photograph upload | JPEG/PNG content validation, size/dimension limits, SHA-256, private content delivery, guarded deletion |
| Object generation | TripoSR on the dedicated GPU worker; validated self-contained GLB with vertex colours |
| Scene reconstruction | COLMAP sparse reconstruction + OpenMVS dense mesh/texturing; self-contained textured GLB |
| Asynchronous tracking | Transactional outbox, three Celery queues, leases/heartbeats, stale-task recovery, cooperative cancellation, retry |
| Browser viewing | React Three Fiber viewer with orbit/zoom/pan, fit, reset, grid, background, fullscreen and live asset metadata |
| GLB download | Authenticated, ownership-scoped streaming download with a safe filename |
| Failed-task handling | Stable error codes and Russian messages, previous result preserved, retry |
| Persistence | PostgreSQL + `app_data` volume; results survive worker/API restarts and redeployments |
| Production packaging | Runtime images, nginx TLS reverse proxy, separate Celery beat, bounded log rotation, scheduled backups |

## 5. Deployment and configuration

Production uses `compose.prod.yaml` layered on `compose.yaml` (plus
`compose.gpu.yaml` for GPU):

```bash
docker compose --env-file .env.production \
  -f compose.yaml -f compose.prod.yaml -f compose.gpu.yaml up -d --build
```

Highlights:

- Only nginx publishes 80/443; PostgreSQL, Redis, the API and workers are
  internal.
- `APP_ENV=production`, `DEBUG=false`, API docs off, Secure cookies, production
  CSRF secret required, HTTPS redirect.
- Celery beat is a separate service; the cleanup worker no longer runs `--beat`.
- A `backup` service writes PostgreSQL dumps and `/data/projects` archives to a
  host directory on `BACKUP_INTERVAL_SECONDS` (daily) with retention.
- Bounded Docker json-file logs.
- The full procedure is in [`../deployment.md`](../deployment.md); the
  environment template is [`.env.production.example`](../../.env.production.example).

## 7. Upgrade and rollback

1. Take an on-demand backup (`... run --rm backup --once`) and copy it off-host.
2. Bump `VERSION`, `APP_VERSION` and the image tags in `compose.prod.yaml`
   together.
3. `docker compose ... up -d --build`; the `migration` service applies new
   revisions before the API starts.
4. Rollback is restore-from-backup unless a tested Alembic downgrade exists;
   database downgrades are not automated.

## 8. Known limitations

Carried from the Phase 9 review and the deployment work:

1. The auth rate limiter is per API process; the MVP runs one replica.
2. Frontend business-logic coverage is 63.9% (overall line coverage 71.5%).
3. `task_execution_service`/`generation_tasks` coverage is 88.6%/85% against the
   90% generation-state target; worker-only paths are live-verified.
4. CI workflows are present and locally executed; no remote CI runner was
   observed in this environment.
5. The real scene dataset is not committed; the E2E scene test needs
   `E2E_SCENE_IMAGES`.
6. Browser performance figures use software WebGL (headless Edge/SwiftShader).
7. The frontend production bundle is ~1.54 MB (436 kB gzip); route splitting is
   deferred.
8. Logout redirects to `/login` rather than the landing page; the session is
   terminated correctly.
9. The committed `plants-1.jpg` fixture is a PNG with a `.jpg` suffix; the
   application correctly rejects the mismatch and E2E uses real JPEGs.
10. Scheduled backups are on the same host by default; copy `BACKUP_HOST_DIR`
    off-host and test restores periodically.
11. The self-signed certificate helper is for local verification only; a real
    deployment must install a trusted certificate.
12. The MVP is single-host Compose; horizontal scaling, object storage and
    Kubernetes are post-MVP (roadmap Section 11).
13. Historical orphan storage directories (~414, ~204 MB) under `/data/projects`
    predate the test-storage isolation and were not bulk-deleted.
14. The object worker image was built before `packaging==26.3` was pinned
    explicitly in `backend/requirements.txt`; the image already contained
    packaging 26.3 (verified), and the pin closes the undeclared-dependency gap
    for the scene worker, whose isolated venv lacked it.
